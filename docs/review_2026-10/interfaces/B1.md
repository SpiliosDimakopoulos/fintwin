# B1 (model calibration): interfaces

Status: final for phase 1.

## `engine/fintwin/stochastic/spec.py`

```python
from fintwin.stochastic import spec
spec.spec()            # "v2-pre" | "v2-rev" | "v3"      (env FINTWIN_SPEC, default "v2-rev" = today's product)
spec.fixes()           # frozenset of active IDs, e.g. {"F1", "F5"}  (env FINTWIN_FIXES overrides)
spec.active("F5")      # bool; "MM-F5" is accepted too; unknown IDs are simply inactive
spec.fixed_share_prior()   # 0.35 for v2-pre and v3, 0.05 for v2-rev (the default of calibrate's assumptions)
spec.label()           # stamp for shard files, e.g. "v3" or "v2-pre[F4,F5]"
spec.LADDER            # ((step name, FINTWIN_FIXES value), ...) for FINTWIN_SPEC=v2-pre
with spec.using("v3", "+F9"): ...   # in-process override (ContextVar), takes precedence over the env
```

`FINTWIN_FIXES` syntax: `F5,F4` replaces the spec's default set; `+F9,-F3` edits it; `none` empties it; empty or unset
means the spec's defaults.

Default fix sets:
- `v2-pre`, `v2-rev`: none. Output is identical to rev3@20b2610 (test `tests/test_B1_parity.py`). They differ only in
  the default fixed-cost prior (35% / 5%) used when the caller passes no `fixed_share_prior`.
  Note: `research/experiments.calibrate` always passes 35% explicitly, so in research v2-pre = the main run.
- `v3`: F1 F2 F3 F4 F5 F6 F7 F8 F10 F12 F13 F14 M3. Off in v3 (§2 extensions, closed for H2): F9, M2.

Ladder (REVISION_PLAN_3 §0.2): run with `FINTWIN_SPEC=v2-pre` and `FINTWIN_FIXES` = `""`, `F5`, `F5,F4`,
`F5,F4,F1`, `F5,F4,F1,F2`, `F5,F4,F1,F2,F3`.

Other workstreams (B2, C*) may use their own IDs with `spec.active("M1")` etc.; add them to their spec's default set
by asking B1/the integrator (the sets live in `DEFAULT_FIXES`).

## Calibration (`stochastic/calibrate.py`): signatures unchanged

`calibrate(c, macro, horizon=12, assumptions=None)` is unchanged. The default `fixed_share_prior` now comes from
`spec.fixed_share_prior()` (5% for the default v2-rev, so the product is unchanged).

New `assumptions` keys (read only when the switch is on): `prior_tau` (F1, default `PRIOR_TAU=0.15`),
`fixed_adj_lambda` / `fixed_adj_lambda_down` (F3, default 0.2 / same), `t_df_pooled`, `t_df_pool_weight` (F7),
`n_param_draws` (F9, default 50).

New module constants and helpers: `TAU_GRID`, `LAMBDA_GRID`, `PRIOR_TAU`, `FIXED_ADJ_LAMBDA`, `FLOATING_BY_SECTOR`,
`select_walk_forward(years, errors, test_year, lag=3, min_obs=500)` (the revision-2 Y-3 rule: lowest median absolute
error over firm-years with year <= Y-3; None if < 500), `_posterior_split` (F1 closed form).

New keys of `p` (present **only** when the switch is on, so v2 dicts are unchanged):

| Key | Fix | Meaning | Consumer |
|---|---|---|---|
| `fixed_share_sd`, `fixed_share_data_weight` | F1 | posterior s.d. of the fixed share; share of the posterior precision from the data | report / C2 |
| `da_imputed_share` | F4 | share of the last 16 quarters whose D&A was imputed (dep_rate x lagged PP&E) | C2 split |
| `m_dev0` | F6 | current cost-ratio deviation (initial `m_dev`) | **B2 model**, TS |
| `t_scale` | F7 | multiplier of the t draws (MAD-consistent: `1/(1.4826 t.ppf(.75, df))`), replaces `sqrt((df-2)/df)` | shocks, TS |
| `t_mix_indep` | F8 | 1.0: separate chi-square mixing for demand and margin | shocks, TS |
| `fixed_adj_lambda`, `fixed_adj_lambda_down`, `fixed_adj_f` | F3 | partial adjustment of fixed costs toward `fixed_adj_f` x deseasonalized revenue | **B2 model**, TS |
| `ma_flag` | F3 | 1/0 acquirer flag (only if `quarters["acquisitions"]` exists) | C2 split |
| `ladder_unknown` | M3 | 1.0 when the maturity ladder is missing/stale (bullets assumed) | C2, web |
| `_param_draws` | F9 | list of dicts {mu, phi, sigma_g, F, v, rho_m, sigma_m[, ocf_ratio][, fixed_adj_f]} | `mc.simulate_paths`, TS |

Changed values under a switch (same keys): `F`, `v` (F1, F2, F10, F12), `rho_m`, `sigma_m`, `rho_gm` (F6), `t_df`
(F7), `dep_rate`, `ebitda_ttm0` (F4), `ocf_ratio`, `tax_rate` (F5), `tau_ar` (F13), `mu` (F14), `floating` (M2),
`maturities_q` (M3). New `_sources` entries: `da`, `tax_rate`, `tau_ar`, `m_dev0`, `fixed_adj`, `floating`,
`_param_draws`.

Data columns read if present (requests/B1.md to A): `quarters["da_missing"]` (F4), `quarters["acquisitions"]` (F3),
`quarters["floating_debt"]` (M2). Each has a fallback.

## Monte Carlo (`stochastic/mc.py`, `stochastic/shocks.py`)

- `mc.simulate_paths(p, scn, eps, levers)`: `simulate` with one `_param_draws` vector per contiguous block of paths
  (F9); exactly `simulate` when there are no draws. `mc.run` now calls it.
- `shocks.draw_shocks`: reads `p["t_scale"]` (F7) and `p["t_mix_indep"]` (F8) when present. Without them the draws
  are bit-identical to revision 2.

## What the TypeScript port (`web/src/engine/**`) must change

Calibration runs only in Python; the browser consumes exported params. So the port is about the new param keys:

1. `types.ts`: add optional `m_dev0?`, `t_scale?`, `t_mix_indep?`, `fixed_adj_lambda?`, `fixed_adj_lambda_down?`,
   `fixed_adj_f?`, `ladder_unknown?`, `fixed_share_sd?`, `da_imputed_share?`, `_param_draws?: Partial<Params>[]`.
2. `shocks.ts` `drawShocks`: `tScale = p.t_scale ?? Math.sqrt((df - 2) / df)`; when `p.t_mix_indep`, draw a second
   `rng.chisq(df)` and scale `m` by its own `tScale / Math.sqrt(w_m)` (draw order: w_g then w_m, after the normals).
3. `model.ts` `simulate`: `mDev` starts at `p.m_dev0 ?? 0`; the F3 fixed-cost recursion exactly as in requests/B1.md
   (B2's `sd_model.py` change), with `rbar = rev / seasonal[(season0 + t) % 4]` taken after the revenue override.
4. `worker.ts` (or wherever `simulate` is called): if `params._param_draws?.length`, split the N paths into
   `min(draws, N)` contiguous blocks (numpy `array_split`: the first `N % K` blocks get one extra path) and simulate
   each block with `{...params, ...draws[i]}`; concatenate. Product exports have no draws unless F9 is switched on.
5. Parity goldens: add a fixture with `t_scale`, `t_mix_indep`, `m_dev0`, and `fixed_adj_*` set. `maturities_q`,
   `floating`, `tau_ar`, `ocf_ratio` etc. need no code change (same keys, different values).
6. Display (WS-E): `ladder_unknown` and `da_imputed_share` are worth a note in the assumptions panel.

## Revision-3 data layer (workstream A) handling in `calibrate`

Triggered by the presence of `quarters["gap"]`; legacy frames (`FINTWIN_DATA_LEGACY=1`) take the revision-2 paths, so
v2-pre/v2-rev stay bit-identical there (checked on cached firms against rev3@4a1c5ea; v3 differs only in the wording
of `_sources["da"]`).
- **Last-row stocks** (`STOCK_FIELDS`): last finite value within `STALE_ROWS = 4` rows; beyond that 0 for working
  capital, debt lines and short investments, the last value ever reported for equity/assets/cash, else the existing
  fallback. Each carry or zero is listed in `_sources["stale"]`.
- **Windows** over "the last n quarters" use reported (non-gap) quarters: `t4`, `t8`, `hist4` (TTM EBIT/EBITDA/interest
  of the rating loop), `rev_ttm`, the cost and cash-floor revenue means. Windows that are NaN-aware already (medians,
  `dropna` cost window, F2 TTM with date-span check) are unchanged.
- `debt_change_8q`: against the last reported debt 8-12 calendar quarters back, else 0. `div_q`: mean of the last two
  reported dividends among the last 4 quarters, else 0 (noted). Interest TTM falls back on `debt0 * coupon / 4`.
- `history_quarters` counts reported quarters.
- **MM-F4** uses `da_missing`, and `da_annual` (fiscal-year D&A / 4) for the missing quarters where available; PP&E
  imputation only where neither exists. `da_imputed_share` is over reported quarters.
