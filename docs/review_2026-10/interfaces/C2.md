# C2 (evaluation pipeline): switches, cache layout, shard keys

Owner files: `research/experiments.py`, `research/distress.py`, `research/calibration.py`, `research/assumption_sobol.py`,
`research/__main__.py`, `backtest/*`. All additions are new keys or optional parameters; no existing key changed meaning.

## 1. Specification switches

| Variable | Values | Effect in C2 |
|---|---|---|
| `FINTWIN_SPEC` | `v2-pre`, `v2-rev`, `v3` (default `v3` in the local fallback) | which fixes are on; research prior mean 0.35 (`v2-pre`, `v3`, ladder rungs) or 0.05 (`v2-rev`) |
| `FINTWIN_FIXES` | comma list, e.g. `F5,F4,F1` (`MM-` prefix accepted) | **replaces** the spec's set of fixes (ladder rungs). C2-local ids: `E1`, `SW17` |
| `FINTWIN_SELECTION` | path to a selection table | second pass: every calibration of cutoff year Y uses the walk-forward τ / λ for Y |
| `FINTWIN_DATA_LEGACY=1` | | restores v2 outcome handling: zero-filled FCF gaps (D4), positional realized quarters (SW-4), 90-day reporting lag (D10), no contiguity check in `_ttm` / `usable` |
| `FINTWIN_MAX_FAIL_SHARE` | float, default 0.10 | `stats` refuses to merge if any stage (≥ 20 attempts) failed more often |

`experiments.fix_active(id)` uses B1's `stochastic/spec.py:active` for `F1`..`F14` once it exists; until then a local
fallback with the same semantics. `E1` is on in `v3` only; `SW17` (real-time NBER state, see §5) is opt-in only.

## 2. Ladder and cache layout

`experiments.LADDER` (REVISION_PLAN_3 §0.2), each rung its own directory `spec_label()`:

| Rung | Environment | Directory |
|---|---|---|
| v2-pre | `FINTWIN_SPEC=v2-pre` | `.cache/research/v2-pre/` |
| +F5 | `v2-pre`, `FIXES=F5` | `v2-pre+F5/` |
| +F4 | `FIXES=F5,F4` | `v2-pre+F5+F4/` |
| +F1 | `FIXES=F5,F4,F1` | `v2-pre+F5+F4+F1/` |
| +F2 | `FIXES=F5,F4,F1,F2` | `v2-pre+F5+F4+F1+F2/` |
| +F3 = v3 | `FINTWIN_SPEC=v3` (F1-F14 and E1) | `v3/` |
| v2-rev | `FINTWIN_SPEC=v2-rev` | `v2-rev/` |

Suffixes: `-wf` (pass with `FINTWIN_SELECTION`), `-legacydata`, `_dry` (any `--limit`/`--cutoffs`).
Other files: `.cache/research/_selection/<label>.json` (τ/λ tables), `.cache/research/_results/<label>.json` (copy of
`research.json` per spec, with the failure summary). Sobol: `.cache/sobol/<label>/`, result also `.cache/sobol/<label>.json`.

### Commands
```
python -m fintwin.research shard i n [--limit 300 --cutoffs 2015,2020,2022]   # dry run: fixed sample (seed 2026)
python -m fintwin.research ladder i n [--limit ... --cutoffs ...] [--rungs v2-pre,v3]
python -m fintwin.research select            # with the rung's FINTWIN_SPEC/FIXES set
python -m fintwin.research stats [--dry]     # with the same env
```
Walk-forward flow for rungs with F1 or F3: (1) `ladder i n` for all i (grid pass: shards evaluate the τ / λ grids);
(2) per rung, `select` → `_selection/<rung>.json` (Y−3 rule, ≥ 500 earlier firm-years, ties to grid order);
(3) `ladder i n` again: grid pass is skipped (stamps match), the `-wf` pass runs at the selected values. The τ grid is
searched at B1's default λ and vice versa (one-dimensional, documented). Paper numbers for v3 come from `v3-wf`.

Expected B1 interface (see `requests/C2.md`): `calibrate(..., assumptions={"prior_tau": x, "fixed_adj_lambda": y})`;
optional module constants `TAU_GRID`, `LAMBDA_GRID` in `stochastic/calibrate.py` override C2's defaults
(0.05/0.10/0.15/0.25/0.50 and 0/0.10/0.20/0.35/0.50).

## 3. New shard keys (per company file)

| Key | Content |
|---|---|
| `spec` | `{name, label, fixes, fixes_env, prior, selection (digest), data_legacy, b1_spec}` |
| `_run` | `{limit, cutoffs}` of the shard run (null in full runs) |
| `failures` | per stage (`panel`, `forecast`, `ets`, `sens`, `grid`, `load`, `filed`, `credit_events`, `covid`, `structural`): `{n, failed: {ExcType: k}, skipped: {reason: k}}` (SW-3) |
| `credit_events` | `{"1.03": [dates], "2.04": [...], "3.01": [...], "2.04_coc_dropped": k, "3.01_coc_dropped": k}`; null if submissions unreadable (M9) |
| `panel[].liquidity` | `{grid: {depth: [P4, P8]}, recession: [P4, P8], base: [P4, P8]}`, P = P(cash + undrawn < 0 within 4/8 q) (E12) |
| `panel[].rec_state0`, `rec_realtime`, `selected` | hindsight vs real-time recession state; τ/λ used |
| `panel[].{base,recession,base_no_loops}.short4/short8` | same shortfall probabilities on every `_run` (also covid scenarios) |
| `panel[].outcome` | + `cash_min_ratio4/8`, `debt_raise4/8`, `outcome_filed`, `outcome_filed4` (D10) |
| `structural` | + `twin_cfo_tot`, `twin_fcf_tot`, `noloops_*_tot`, `twin_ebitda_tot`, `twin_capex_tot` (median of path totals, E1); `twin_cfo_sm`, `twin_fcf_sm` (v2 sum of medians); `e1` (bool); `twin_cfo_point`, `twin_fcf_point` (the spec's point: `_tot` if E1 else `_sm`); `dens.{cfo,fcf} = {q: 21 quantiles at QLEVELS, mean, sd, crps, pit}` (E2, all paths, % of TTM revenue); `sens[*].cfo_tot/fcf_tot`; `grid` (τ/λ variants: `{cfo, fcf, cfo_sm}`); `sens_failed` |
| `forecasts[]` | + `filed` (first filing date of the target), `crps_rw_emp`, `pit_rw_emp` (E10) |

Existing keys unchanged: `twin_cfo` is still the list of per-quarter medians (so `sum(twin_cfo)` = old point).

`backtest/batch` cases: + `filed`, `crps_baseline_emp`; company file + `_stamp`; `calibration.json` + `vars.*.skill_by_horizon`,
`stamps`, written with `allow_nan=False` via `export._clean`.

## 4. New evaluation functions (for C1's `stats.main`)

| Function | Input | Output |
|---|---|---|
| `calibration.density_section(panel)` | `stats.load` panel frame (uses `st`) | E2 / §2.2 B1: CRPS, PIT hist, DM (two-way, t(G−1)) vs Gaussian and empirical residual densities around N3 (train ≤ Y−3), success flags |
| `calibration.section(fc, panel)` | unchanged signature | + `conformal90_asym`, `pit_hist`, `interval_score90`, `coverage_tests` (Christoffersen), `pit_hist_rw_emp` (E13); conformal windows use `filed` (D10) |
| `calibration.dm_by_horizon(fc)` | forecasts frame | E10: skill + firm-clustered DM per var × horizon vs `crps_rw` and `crps_rw_emp` |
| `distress.liquidity_frame(cache)` | shard directory | one row per firm-year (reads shards itself) |
| `distress.liquidity_section(df, b)` | that frame | E12 / §2.2 B2: realized-shock (2015, 2020, 2022) and Recession versions, 4 and 8 q, labels `shortfall` and `credit_event`; Brier, log, Murphy, reliability; logit and Altman Z'' trained on labels observable at the cutoff; BSS with year-block and firm-block CIs; `success` |
| `distress.credit_section(df, b)` | same frame | M9 / B3: AUC for `ce8`, `bk8`, `acc8`, `delist8`, `ce4` |
| `distress.event_scores(panel)` | `stats.load` panel | E8 for the structural decisions (Brier, log, Murphy, BSS vs climatology ≤ Y−3) |
| `distress.prob_scores/brier/log_score/murphy/block_ci/fit_logit` | arrays | building blocks |
| `experiments.failure_summary(shards)` | list of shard dicts | pooled SW-3 counts |

Realized shortfall label (pre-specified in `distress.py` before any rev-3 run): within k quarters, a credit event
(8-K 1.03/2.04/3.01, merger-related 2.04/3.01 dropped) **or** cash-like < 25% of opening with total debt up > 5% of TTM
revenue. The model event (cash + undrawn < 0) is not observable.

## 5. Other behaviour

- SW-4: realized windows are cut at the first gap (60–125 days between quarter ends), `backtest.batch.contiguous_prefix`.
  Workstream A's calendar helper can replace it; semantics are the same (NaN rows also fail the finiteness checks).
- D4: outcome FCF totals/burns are NaN if any quarter is missing (`walk_forward`, `batch.covid_row` too).
- SW-15: `features` no longer raises on zero balance items (NaN → None).
- SW-17: `SW17` switch sets `rec_state0` from NBER announcement dates (`NBER_ANNOUNCED`); off in every spec, the
  real-time flag is always stored (`rec_realtime`) so its effect can be counted.
- SW-18: `macro_quarterly` and `spreads_asof` are cached per cutoff in `experiments` (copies returned).
- P8: Sobol uses `scipy.stats.qmc.Sobol(scramble=True)`, N = 256, CIs resample firm-years and design points, adds
  `elasticity_ratio`; with F1 on, `prior_weight` → `prior_tau` (0.02–0.60). Rows store `twin` (spec point) and `twin_sm`.
- `stamp()` now also hashes the content of `FINTWIN_SELECTION`; code digest cached per process.
