# B2 (model mechanics): interfaces and switches

No public signature changed. `simulate(p, scn, eps, levers)` and `build_scenario(knobs, horizon)` are as before. All
additions are optional `p` keys, optional `levers` keys, new output keys (present only when their switch is on), and
new functions.

## Switches

| id | what | default in v2-pre / v2-rev / v3 |
|---|---|---|
| `F11` | MM-F11: immaterial interest + net cash -> ICR floored at 2.5 (BBB) for rating, spread, access, B1 stress, `h_cov`, and the `icr` output | off / off / **on** |
| `M1` | maintenance covenant, revolver freeze on breach, revolver maturity | off in all three (extension) |
| `M4` | sector multiplier on the sales depth (`presets.sector_knobs`) | off in all three (extension) |
| `M5` | REIT / utility payout floor | off in all three (extension) |
| `F6` | MM-F6, model side: `m_dev` starts at `p["m_dev0"]` instead of 0 | off / off / **on** (B1 `V3_FIXES`) |
| `F3` | MM-F3, model side: partial adjustment of fixed costs (`fixed_adj_lambda`, `fixed_adj_lambda_down`, `fixed_adj_f`) | off / off / **on** (B1 `V3_FIXES`) |

- **Resolution order.**
  1. A `levers[id]` key (bool) for one run, e.g. `levers["M1"] = True`.
  2. `fintwin.stochastic.spec.active(id)`, which is imported directly now that B1's module is merged.
  3. The env fallback in `sd_model.active`, used only if that import fails.
- **Fallback semantics.** Plain `FINTWIN_FIXES` list, else the `FINTWIN_SPEC` defaults with v3 = {F3, F6, F11}. An unset spec counts as `v2-pre`. B1's own default when unset is `v2-rev`, which gives the same outputs from this module.
- **F3 and F6 keys.** They are used only when the switch is on. With the switch off, the keys are ignored even if present (tested).
- **Identity proof.** `tests/test_B2_identity.py` keeps a verbatim copy of the rev3 `simulate` from before B2. It checks bit-identity of every output in these cases:
  - 3 synthetic firms × all 9 presets, with env unset, `v2-pre` and `v2-rev`, and with explicit `False` levers;
  - `F3,F6` on without their keys, or with λ = 0 and `m_dev0` = 0;
  - F3/F6 keys present with the switches off.

## New `p` keys (all optional)

| key | default | used by |
|---|---|---|
| `rev_ttm0` | `4 * base_rev0` | F11/M1 materiality before the first simulated quarter. **Request to B1:** set it to the real TTM revenue in `calibrate` |
| `icr_materiality` | `0.001` (interest ≤ 0.1% of TTM revenue = immaterial) | F11, M1 ICR test |
| `cov_max_nd_ebitda` | `4.0` (None disables) | M1. Fails if net debt > 0 and (EBITDA_TTM ≤ 0 or ND/EBITDA > limit) |
| `cov_min_icr` | `2.5`, EBITDA_TTM / interest_TTM, tested only if interest is material (None disables) | M1 |
| `cov_cure_q` | `1` | M1: breach when the test fails on more than `cov_cure_q` consecutive quarter-ends |
| `cov_revolver_avail` | `0.0` | M1: share of the commitment still available after a breach. The commitment is `min(cap, max(drawn, avail*cap))`, sticky, and drawn balances are not accelerated |
| `revolver_maturity_q` | `None` | M1. At quarter t = q, before the draw: `termed = revolver*refi_ratio*access` becomes term debt at `mkt_rate` (coupon blended), the rest is repaid from cash, and the revolver and its commitment are 0 from then on |
| `payout_class` | `""` (`"reit"` / `"utility"`; helper `sd_model.payout_class(sic)`) | M5. **Request to B1/A:** set it in `calibrate` from the SIC |
| `payout_floor_ni` | reit 0.9, else 0 | M5: `div = max(div, floor*max(NI,0))` every quarter (IRC §857(a)) |
| `payout_keep_div` | utility 0.65, else 0 | M5: under B1 stress, with `cut_payouts`, `div = max(div, keep*div_q)` |

- **Covenant timing.** The test runs at quarter end, on TTM figures after the TTM roll. The availability cut applies to that quarter's reported `undrawn`/`liquidity` and to draws from the next quarter on.
- **Equity issuance (M5).** It remains the existing `levers["issue_equity"]` (default False). When on, it fills `cash_floor - cash` whenever `access > 0`, so it is blocked in a credit freeze. No new switch.

## New outputs (only when M1 is on)

- `out["cov_breach"]` [N,T]: 1.0 from the breach quarter on, sticky. It is the breach flag per path, with `[:, -1]` for the whole horizon.
- `out["revolver_avail"]` [N,T]: the undrawn commitment, as used in `liquidity`.

## New functions

- `sd_model`:
  - `first_covenant_breach(out)`: per path, the first breach quarter, or -1.
  - `p_liquidity_below(out, x, n)`: P(min over the first n quarters of cash + undrawn < x).
  - `maturity_wall(p, T)`: the contractual ladder by quarter.
  - `decision_outputs(out, p, x=None, n=None)` returns:
    - `runway_q_median`, `runway_q_p10` and `runway_censored_share`. The runway is the first quarter with liquidity < 0, or T if there is none.
    - `funding_gap_p50`, `funding_gap_p95`, `funding_gap_mean` and `p_funding_gap`. The gap is the max over t of max(cash_floor − cash, 0).
    - `maturity_wall`.
    - `revolver_due` if a maturity is set.
    - `p_liquidity_below` if x is given.
    - `p_cov_breach` and `first_cov_breach_q_median` if M1 is on.
  - It is not wired into `mc.summarize`, which is B1's file. Request: add `"decisions": decision_outputs(out, p)` to `summarize` or to the API, behind nothing (pure addition).
- `ratings`: `ICR_MATERIALITY`, `NET_CASH_ICR`, `effective_icr(icr, interest_ttm, revenue_ttm, net_cash, materiality)`.
- `presets`:
  - `PRESET_SOURCES` gives a source for every product preset. `PRESETS` itself is unchanged, so export and web are unchanged.
  - `SUPERVISORY_PRESETS` has `fed_2026_severely_adverse` and `esrb_2025_adverse`, each with a `source`. They are kept out of `PRESETS` so that `export.py` does not change. Add them to the product deliberately if wanted.
  - `all_presets()`.
  - `sector_shock_table(drops, sectors, min_n=6)`, `load_sector_shocks()` (reads `fintwin/data/sector_shocks_2020.json` `{"shocks": {...}}`), `sector_multiplier(sector, table)` (the industry median over the all-firm median, clipped to [0, 3], 1.0 if unknown) and `sector_knobs(knobs, sector, table=None, on=None)` (scales `sales_depth`, capped at 0.95, only if M4 is on).
- `reverse_stress.headline(rs, level="p50")`: a one-sentence reverse-stress headline.

## What the TS port (web/src/engine) must mirror

1. **`simulate` branches**, behind the same three flags: `F11`, `M1`, `M5`.
   - Keep the order of operations exactly:
     - `icr_prev` is effective (F11).
     - Then the payout floors: utility keep inside the `cut_payouts` block, REIT floor after it, regardless of the lever.
     - Revolver maturity runs after the debt block and before the backstops, using this quarter's `access` and `mkt_rate`.
     - Draws are capped by `rcap`.
     - After the TTM roll: `rev_hist` roll, then the effective `icr` (F11, net cash = −net_debt at quarter end), then the covenant test and the `rcap` update, then `undrawn = max(rcap − revolver, 0)`.
   - `rev_hist` starts at `rev_ttm0/4` (else `base_rev0`) in each of 4 slots, and it rolls in `rev` (the post-shock revenue).
   - F11 `icr_fixed` (the `loop_r1` off ablation) uses `interest_ttm0`, `rev_hist` and `cash0 − debt0`.
2. **The constants**: `ICR_MATERIALITY`, `NET_CASH_ICR`, `COVENANT_DEFAULTS` and `PAYOUT_DEFAULTS`.
3. **The outputs** `cov_breach` and `revolver_avail`, plus the pure helpers of M7. They are the same formulas, and percentiles use linear interpolation as numpy's default does.
4. **The presets.**
   - Nothing is needed unless the product adds `SUPERVISORY_PRESETS`; they use existing knobs only.
   - `sector_knobs` is only needed if the browser offers M4.
5. **Parity goldens.** Add a golden with each of F11, M1 (with `revolver_maturity_q`) and M5 on. The existing goldens must not change.
6. **MM-F6.** If F6 is on, `m_dev = full(N, p.m_dev0 ?? 0)` before the loop. Otherwise it stays zeros.
7. **MM-F3.**
   - Before the loop: if F3 is on, set `lamUp = p.fixed_adj_lambda ?? 0`, `lamDn = p.fixed_adj_lambda_down ?? lamUp`, `fAdj = p.fixed_adj_f ?? 0` and `F_t = full(N, p.F)`. Otherwise `lamUp = lamDn = 0`.
   - In the loop, where `fixed` is computed: if `lamUp > 0 || lamDn > 0`, then
     - `F_t *= 1 + infl`;
     - `rbar = rev / seasonal[(season0 + t) % 4]`, using `rev` after the sales shock and `revenue_override`;
     - `gap = fAdj * rbar - F_t`;
     - `F_t += (gap > 0 ? lamUp : lamDn) * gap`;
     - `fixed = F_t * cut_mult`.
   - Otherwise keep the v2 expression `F * (1 + infl) ** (t + 1) * cut_mult` exactly. Do not replace it with the recursive product: that is not bit-identical, because of rounding.
   - Add one golden with F3 at λ = 0.5 and one with F6 at `m_dev0 = 0.04`.

## Known limits

- M4 is partial: no multiplier table ships.
  - The paper's industry shocks are computed in `research/distress.exposure` from census shards that are not on this PC.
  - The integrator must produce `fintwin/data/sector_shocks_2020.json` on the server: `sector_shock_table(xs.real_rev_drop, xs.sector)`, FF12 sector, plus `"source"`/`"n"` keys.
  - Until then every multiplier is 1.
  - For research use, note that `exposure` uses leave-one-out medians. The preset table is a plain median.
- In the supervisory presets, revenue is mapped from real GDP by one stated rule: the gfc_2008 trough scaled by the GDP-decline ratio. Durations not stated in the sources are marked as assumptions in code comments. The ESRB short-rate row was read from interleaved PDF text, so the preset sets no rate shock.
- In M1, a covenant breach does not accelerate debt or cut term-debt market access (no cross-default), and the breach is never waived.
